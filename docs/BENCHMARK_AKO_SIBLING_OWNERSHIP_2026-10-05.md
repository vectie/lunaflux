# AKO sibling ownership: fewer instructions, insufficient latency hiding

## Decision

Three offline gate/up ownership schedules were generated by the existing pure
physical planner, compiled and measured on Spark. None is promoted. The
128-row schedules regress; the 64-row/8-consumer schedule does not reliably
improve the complete MLP chain with distinct layer-weight addresses.

This round produces **no new serving-throughput claim**. The serving selector,
runtime bundle and production compiler defaults are unchanged. It does not
replace the previous end-to-end results in
[the ingress-routing report](BENCHMARK_AKO_INGRESS_ROUTING_2026-10-05.md).
No vLLM/SGLang service was rerun during this experiment.

## Hypothesis and compiler boundary

The previously measured async segmented transport already works. This trial
asks whether larger row reuse and coowned gate/up accumulators can remove
shared-memory epilogue handoffs without sacrificing effective parallelism.

The selected baseline splits siblings across consumer planes. The alternatives
exceed the split-plane reuse partition's row capacity and use the planner's
ordinary product partition, keeping both sibling accumulators with one
consumer. Segmented, overlapped transport is explicitly retained: this is not
another synchronous-to-async comparison. All alternatives use K32, two stages,
one fragment stage and a 64-column output tile.

Relevant paths:

- `kernels/luna_projection_tile_compiler/physical_pipeline.mbt`: pure
  distribution, storage and transport choice.
- `kernels/luna_cuda_projection_aot/source_sibling_reuse.mbt`: split-plane
  lowering with shared epilogue publication.
- `kernels/luna_cuda_projection_aot/source_sibling_pipeline.mbt`: consumer-owned
  gate/up fragments and epilogue.
- `kernels/luna_cuda_projection_aot/ako_sibling_domain_wbtest.mbt`: opt-in exact
  source export and unchanged-down regression.

No source-text substitution, model-name branch, new IR layer, request-path JIT
or production profiler dependency was introduced. The experiments demonstrate
a physical-plan trade-off, not a failure of functional compiler layering.

## Fresh hardware-counter explanation

Nsight profiles the baseline and alternative primary at 2048 tokens in a
separate correctness-only process. Counter replay times are **not** unprofiled
benchmark times. Each alternative has its own paired baseline capture; do not
compare replay absolute times across those processes.

| Metric | Baseline paired with r64-c8 | r64-c8 |
| --- | ---: | ---: |
| Executed warp instructions | 93020160 | 57507840 |
| Registers/thread | 58 | 102 |
| Active warps / scheduler active cycle | 7.88 | 3.92 |
| Eligible warps / scheduler active cycle | 0.75 | 0.34 |
| Issue-active fraction | 31.51% | 23.72% |
| Barrier-stall ratio per issue-active | 7.72 | 2.44 |
| Long-scoreboard ratio per issue-active | 2.47 | 3.56 |
| Average warp latency / instruction issued | 25.00 cycles | 16.55 cycles |
| Tensor activity, elapsed-normalized | 34.99% | 35.53% |
| Local spilling requests | 0 | 0 |

The new ownership removes about **38.18% of instructions** and reduces the
normalized barrier ratio about **68.39%**, but active warps halve and eligible
warps fall about 55%. The register footprint increases about 76%. Tensor
activity barely changes; long-load dependency pressure does not disappear.
This is evidence of a register-residency/latency-hiding trade-off, not spilling.
The stall ratios are normalized counters, not additive milliseconds or percentages
of the end-to-end gap.

The 128-row alternatives reproduce the trade-off more severely:

| Metric | r128-c16 | r128-c8 |
| --- | ---: | ---: |
| Executed warp instructions | 54423552 | 51271680 |
| Registers/thread | 93 | 148 |
| Active warps / scheduler active cycle | 3.99 | 2.00 |
| Eligible warps / scheduler active cycle | 0.30 | 0.19 |
| Issue-active fraction | 17.72% | 16.45% |
| Barrier-stall ratio per issue-active | 3.92 | 0.90 |
| Local spilling requests | 0 | 0 |

Fewer CTAs, instructions and barriers alone are not a performance objective.
These measurements reject the hypothesis that simply increasing row tiles or
removing every epilogue handoff is sufficient.

The next falsifiable schedule should keep enough consumers while making sibling
ownership explicit: test 64-row coownership with 16 consumers, so fewer rows of
both products remain live per consumer. This distinguishes register residency
from the already-tested copy pipeline. Only then consider fragment-window
lifetime changes; do not add another IR layer or retune unrelated attention.
