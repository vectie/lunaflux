# Numerical correctness and prediction quality

## Decision

Correctness is not “reproduce one installed implementation at every bit.”
Keep exact arithmetic tests where the declared contract requires them, but
separate semantic validity, finite-precision compatibility, prediction changes,
and task/media quality. No existing tolerance or reference is changed by this
decision. New arithmetic remains experimental until its intended contract and
model-level consequences are established.

The installed original, LunaFlux, vLLM, and SGLang are implementations to compare,
not four independent mathematical oracles. Shared kernels create correlated
agreement. Higher precision is a useful local control, not automatically the
author's intended quantized model. An implementation's self-variation across
batch, prefill/decode, topology and hardware is a measured control, not an
automatic acceptable-error threshold.

## Why the current diagnosis is insufficient

The completed FP8-projection chain at

**14.551407124895%**, versus **13.656348080%**. Neither chain includes a final

large reference entries and must not substitute for per-position results.

This is not proof of worse text quality, nor proof of improvement. It shows that
local compatibility, propagated hidden-state differences and useful quality
are different measurements. Preserve the unsuccessful full-chain result.

## Evaluation ladder

1. **Semantic invariants:** same checkpoint interpretation, tokenizer/vocabulary,
   masks, positions, quantization conventions, cache visibility and state
   transitions. Broken invariants are bugs irrespective of average quality.
2. **Matched operator replay:** identical actual operands and previous state,
   inspect outputs and next state. Exact equality is required only when claimed
   by the arithmetic contract; other comparisons report differences, not passes.
3. **Teacher-forced model replay:** every implementation receives the same
   prescribed tokens; compare raw final-head logits predicting each next token.
   Do not compare states after free-generation prefixes diverge.
4. **Held-out quality:** language/code/reasoning/long-context tasks, plus actual
   image/video/audio quality and prompt alignment. No tuning on the acceptance
   set. Media additionally needs matched noise, conditioning and sampler state;
   an LLM probability test cannot validate a diffusion trajectory.
5. **Performance:** normal serving under the fixed quality requirements. Report
   diagnostics/deterministic controls separately from normal-mode throughput.

Use sequence-level paired uncertainty estimates when there are enough independent
held-out sequences. Correlated token positions are not independent samples. Report
macro averages across cases as well as token-weighted averages and worst/tail
cases. Never add layerwise relative norms to claim a whole-model error bound.
Prescribed next tokens should come from a fixed external held-out corpus when
assessing quality. Tokens generated by the reference are not automatically
correct answers; NLL on such a sequence only measures its likelihood.

## Teacher forced distribution comparison

`scripts/compare-teacher-forced-logits.mbtx` is an offline CPU tool, independent
of a GPU backend. It compares two capture manifests symmetrically; neither input
is named “ground truth.” Run all six pairs for four implementations, and run
self-comparisons across repeats/configurations separately. It reports:

- Jensen–Shannon divergence and both directional KL divergences (natural logs);
- total variation, top-1 agreement, deterministic top-k set overlap;
- both top-1/top-2 logit margins and the other implementation's winner gap;
- prescribed next-token negative log likelihood, signed NLL change and entropy;
- per-position reports and case-balanced versus token-weighted summaries.

Stable log-softmax is computed in CPU F64, subtracting the row maximum before
normalization. No probability-floor epsilon, truncated top-k distribution,
payload hashes, tolerance waiver, pass flag, or production-path instrumentation.
One complete finite F32 vocabulary row is read at a time from each implementation.
The adapter must export logits before temperature, penalties, sampling and masks
that are not part of the model. Top-k-only API responses are not complete logits.

Capture manifests include literal token sequences, prediction positions,
checkpoint and vocabulary/tokenizer labels, backend/mode/configuration and state
policy descriptions. Literal tokens and positions are compared directly. Labels
are declarations, not cryptographic identity or proof that an adapter obeyed the
protocol. Adapter tests must independently establish the head/position mapping,
fresh request state, and absence of sampling transforms.

### Capture format and usage

Both manifests use the following schema. Each path is absolute and contains
exactly one little-endian F32 row in vocabulary-ID order. `position=0` means
logits after consuming `tokens[0]`, predicting `tokens[1]`; tokens include the
literal BOS/template tokens supplied to the engine. `first_position` and the
logit file count describe a contiguous scored interval. Require identical
intervals and token sequences; partial windows remain explicit, never presented
as all-position coverage.

```json
{
  "schema": "lunaflux-teacher-forced-v1",
  "implementation": "lunaflux",
  "checkpoint": "literal checkpoint revision/quantization label",
  "tokenizer": "literal vocabulary and tokenizer revision label",
  "vocabulary": 3,
  "configuration": "commit; hardware; TP; batch; prefill/decode; arithmetic plan",
  "state_policy": "fresh request, causal positions starting at zero",
  "logit_semantics": "raw-model-full-vocabulary",
  "cases": [{
    "id": "heldout-case-1",
    "tokens": [0, 1, 2],
    "first_position": 0,
    "logits": ["/absolute/position0.f32", "/absolute/position1.f32"]
  }]
}
```

```sh
moon run scripts/compare-teacher-forced-logits.mbtx LEFT.json RIGHT.json NEW_REPORT.json 2
moon test scripts/compare-teacher-forced-logits.mbtx --deny-warn
```

The final argument is the top-k overlap diagnostic (1 through min(vocabulary,128)).
The report is descriptive: thresholds must be chosen before evaluating a new
candidate, anchored to task requirements and a declared corpus. Baseline
variation cannot retrospectively justify a failed candidate. No synthetic test
or retained hidden-state corpus is described as a new model-quality benchmark.

## Compiler responsibilities

The intended flow remains:

```text
model operations + logical state
  -> compositional finite-precision program
  -> legal rewrites / explicit arithmetic alternatives
  -> complete fusion/execution plan
  -> physical tiles, memory lifetimes and effect ordering
  -> private device lowering -> AOT execution

semantic boundary mapping + executed plan
  -> offline replay -> operator / prediction / held-out quality measurements
  -> EXTERNAL quality-constrained complete-plan selection

external selection -> requests a declared numerical program from compiler
compiler legality NEVER depends on comparison scores or a reference engine
```

The existing precision IR already owns reduction, scaling, quantization and
rounding laws. Extend it incrementally at real consumers, rather than introduce
a parallel family of disconnected configuration flags:

| Capability | Required implementation boundary |
| --- | --- |
| Finite-precision expressions | Implemented typed F32/BF16 expressions and ascending folds at the learned compressor. Existing scale, quantization and tree laws remain in the same precision IR. |
| Rewrite classification | Implemented a closed rule checker and exact simplifier consumed by lowering. Conditional exact BF16 roundtrip; analytic local BF16 conversion bound; unknown transformations rejected. No empirical proof constructor. |
| State transition semantics | Compressor effects now use existing `parallel_ir`; its actual prepared launch order consumes that schedule. In-place writes are explicit, not mislabeled rollback. |
| Differential replay | Eight compiler-described, already materialized compressor boundaries bind to borrowed frame allocations. Capture/evaluation remains offline; no token-step copies. This is not automatic instrumentation of every fused operator. |
| Selection | Offline `benchmarks/numeric_selection` filters numerical programs independently of measured complete-plan latency/memory. Quality filtering and state/layout equivalence remain caller responsibilities, not results of a scalar check. |

The learned compressor now constructs projection, gate bias, maximum,
denominator, weighted sum, BF16 publication and learned RMS expressions in
`precision_ir`. Private CUDA lowering only spells their primitives. Ordered
folds carry seed bits, extent and update expressions. An explicitly requested
projection FMA is a different numerical program, not an equivalent rewrite.
Default generated ratio-4/ratio-128 sources remain byte-identical.

### What the rules establish—and do not establish

`NumericExpression` checks types and input slots. Preconditions such as finite
BF16 inputs or a declared absolute input bound are part of the operator contract,
not inferred from observed samples. Exact simplification can remove a finite
BF16→F32→BF16 roundtrip even inside a larger pure expression. It excludes NaN
payload assumptions. It does not reassociate sums, contract FMA, move scales,
replace `expf`, or drop rounding boundaries based on test agreement.

The one bounded rule concerns F32→BF16→F32, with nearest-even rounding, gradual
underflow and `|x| ≤ M ≤ 2^126`. Normal BF16 rounding has absolute error at most
`|x|/256`; subnormal rounding at most `2^-134`. The implementation conservatively
returns `M/128 + 2^-132`, allowing margin for computing the bound in F64. This
local bound needs an explicit local approximation budget; the exact gate rejects
it. It is not a whole-model error budget or permission to sum observed layer
norms. The rule implementation and primitive contracts are trusted code with
tests and mathematical reasoning, **not a machine-checked proof of the compiler**.

Device natural exponential/reciprocal-sqrt remain named backend primitives,
not a claim of correctly rounded transcendental functions across hardware.
Different numerical programs may be legitimate experiments; matching vLLM,
SGLang or the installed original does not change their semantic classification.

### State and replay ownership

The pool's reserve stage may reset/poison history; pooling mutates retained KV
and gate state; final publication advances the history counter. Existing
`parallel_ir` derives read/write hazards and an explicit normalization→publish
dependency. The prepared frame consumes that schedule once, before serving.
There is no new token-step allocation, dependency analysis or synchronization.
Abort/retry must restore all three persistent buffers using the enclosing
snapshot owner, or discard request state. A history counter alone is not rollback.

Replay descriptors identify source stages, allocation slots, scalar types,
capacities and live-row count fields in append. Captures require producer
completion and live extents; unused capacity is not a numerical observation.
The frame exposes borrowed buffers without copying, waiting or evaluating.
Existing physical tests cover chunk boundaries, zero-length chunks, retained
state and rejected position gaps. They do not prove every cancellation path.

### External selection boundary

`benchmarks/numeric_selection` can select the fastest measured complete plan
within a memory ceiling after checking its declared scalar programs and folds
against an exact-program requirement. Seed and extent changes are rejected.
It cannot use a faster time, large error allowance, or output agreement to
authorize an unknown rewrite. It is only the numerical portion of offline
plan selection—not a verifier of all caller-supplied state/layout bindings.
Different-program quality experiments remain external and explicitly named.

`scripts/validate-numerical-program-boundary.mbtx` checks compiler package
dependencies transitively for evaluation/benchmark imports, reading only package
declarations. It is a development architecture check, not a payload integrity
scan. The teacher-forced comparator still emits descriptive measurements only.

   and further analytic rewrite rules require their own real consumers.

## Implementation validation

The comparator passes 9/9 tests on native and 9/9 on the default Wasm script
backend with warnings denied. Tests cover analytic distributions, constant-logit
shift invariance, extreme tails, directional KL, ties and tiny-margin flips,
input/position rejection, nonfinite/truncated rows, case weighting and real
file-to-report execution without overwriting. Script type-check and formatting
checks pass. Targeted precision-IR interface generation has two existing
derived-method migration warnings, zero errors and no interface change.

These are tool tests, not real model-quality results. The comparator-only phase
changed no GPU workload, production arithmetic, model reference or tolerance.
The recurring monitor stays cancelled.
