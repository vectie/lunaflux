# RGB8 media boundary

`Image` owns immutable, interleaved, top-to-bottom RGB8 bytes. `from_rgb` adapts
already decoded frames; `decode` accepts in-memory PNG/JPEG and returns the same
type. File/network access and model preprocessing belong to callers. Native
decoding and its temporary C storage finish before this API returns.

The decoder uses vendored
[stb_image](https://github.com/nothings/stb/blob/9600522de53973336fa033a289858a4354cbb04c/stb_image.h),
revision `9600522de53973336fa033a289858a4354cbb04c`. Its MIT/public-domain license
is preserved in the header. A local JPEG correction consumes entropy bits
already buffered before a prefetched scan marker; it preserves the ABI and SIMD
path. Only PNG/JPEG memory decoding is enabled; no Python,
filesystem API or runtime library download is required. Dimensions/pixel count
are admitted before full decoding. Encoded and decoded sizes remain bounded.

PNG alpha is discarded, matching an explicit RGB conversion rather than
background compositing. Grayscale becomes three equal channels. This first
profile accepts 8-bit PNG/JPEG; 16-bit PNG is rejected. `decode` retains stored
raster orientation. `decode_oriented` applies standard EXIF orientations 1–8
from JPEG APP1 or PNG eXIf, including either TIFF byte order. Transformed frames
use one additional RGB buffer; malformed/unrecognized orientation retains the
stored raster. MiniCPM file and HTTP ingress use this oriented entry point.
ICC/gamma and XMP transforms are not applied.
Camera adapters should provide RGB frames in the intended physical orientation.
Color-profile transforms require separate upstream-profile qualification.

The independent pinned Transformers/Pillow ingress corpus covers126 cases:
orientation matches exactly over188,790 RGB bytes when both paths consume the
same native-decoded raster, and all72 PNG cases match the full Pillow result.
The54 JPEG cases have maximum channel difference3; full JPEG bit parity and
its effect on model outputs remain unverified. See the
[image-load oracle](../../tests/minicpm_v47_image_load_oracle/README.md).

The small PNG fixtures are generated by the MoonBit fixture script, and JPEGs
are encoded offline with `cjpeg`; neither encoder is a runtime dependency:

```sh
moon run tests/rgb8/make_fixtures.mbtx /absolute/path/lunaflux /absolute/path/cjpeg
moon run scripts/test-rgb8-native.mbtx /absolute/path/lunaflux NEW_SANITIZER_OUTPUT
```

The standalone ASan/UBSan probe compiles the exact C decoder with a test byte
ABI, checks known colors/alpha/grayscale and baseline/progressive JPEG, and
exercises every truncated fixture prefix. Codec malloc/realloc/free counters
must balance after every call. The full generated-MoonBit/native ASan fixture
separately uses the real MoonBit byte ABI. Sanitizer runs disable leak detection;
the standalone codec counters cover temporary decoder allocation release.

```mbt check
///|
test "camera frame and decoded image use the same representation" {
  let image = @rgb8.Image::from_rgb(
    b"\xff\x00\x00\x00\xff\x00",
    width=2,
    height=1,
    maximum_pixels=2,
  )
  assert_eq((image.width(), image.height()), (2, 1))
  assert_eq(image.data().length(), 6)
}
```
