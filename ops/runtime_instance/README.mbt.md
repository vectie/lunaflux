# Pinned native runtime owner

The production preparer consumes the single digest-suffixed launch argument,
opens independent model, kernel, and policy authorities, joins the existing
descriptor/policy/tokenizer admissions, closes policy authority, and checks the
exact assigned CUDA device before verifying the worker executable or creating
a process/listener. On platforms without the admitted CUDA target it fails
truthfully and can never publish Ready.

`preflight_release` reuses the same recipe-specific descriptor, policy,
tokenizer, capacity, and worker-executable joins, then stops before the CUDA
probe. It closes policy, model, and kernel authority before returning one
canonical root-free digest record. `lunaflux validate-release
ABSOLUTE_DEPLOYMENT_ROOT#sha256=...` exposes that offline proof without adding
compiler, JIT, process, device, or listener authority. It authenticates an
already materialized deployment namespace; it does not compile kernels or
replace the exact no-overwrite deployment-bundle assembler.

`preflight_materialized_release` is the offline staging counterpart. It reads
the exact canonical deployment-bundle evidence, opens only fixed bundle
descendants, and constructs typed `ApprovedRootMaterializationView` values that
pair pinned no-follow source roots with the launch's final absolute labels. The
same closed legacy/I8 descriptor and instance joins run once, and the staged
worker bytes are snapshot-verified for the exact final activation path. All
source roots close before the returned evidence. The transactional shell
materializer invokes this command before removing its no-overwrite cleanup
claim and records both the tool digest and semantic evidence digest.

The authenticated launch recipe selects exactly one descriptor and instance
join. Legacy v1 keeps the existing path. Production I8 v2 uses the strict I8
descriptor, I8 instance admission, and opaque I8 online-release wrapper; it
cannot probe or fall back to the legacy loader. Both recipes converge on the
same framed-service preparation, listener, restart, lifecycle, and cleanup
owner. I8 host admission checks ordinal and target facts, while the child must
independently re-observe exact memory/numeric facts and finish executor
construction before readiness. This source path is not physical CUDA evidence.

Successful lower preparation retains only private model/kernel duplicates in
the existing online worker/service owner. The operator first captures that
ready-or-cleanup outcome, then closes both borrowed originals. A Busy close
retains only the still-live original for bounded retry; a consumed close error
fails the instance without retrying a potentially reused descriptor. Health
and readiness are independent. Only a bound listener plus a live server makes
the owner Ready; failure and drain clear readiness. Cooperative `progress`
drives the existing bounded lower transitions and retains retryable cleanup
authority after failures.

The same singular owner binds a separate loopback operational listener and
publishes its actual admitted address through `operational_local_addr`. The
listener projects fixed `/healthz` and `/readyz` observations from the owned
inference server; it introduces no second lifecycle authority. Production
`Ready` requires both listeners and the service to be ready. Drain intent is
applied to the inference source first, making readiness false before that
listener closes; the operational listener remains observable through source
drain and is closed last. Qualification provenance never receives production
readiness.

`require_spawned_physical_handoff` observes only the exact successful
post-child-Ready, pre-listener state. It proves that the authenticated spawned
child constructed and transferred its physical executor, while deliberately
granting no traffic-readiness or plan-execution claim. The dedicated approved
tiny-model campaign harness consumes this proof and drains without ever binding
a listener.

The optional spawned benchmark adapter is compiled beside the operator owner
but is not called by normal preparation, `progress`, or request serving. It
depends only on the authority-free bounded benchmark collector and its
immutable evidence types. Keeping the collector call at this boundary avoids
forged or retrospectively inferred timestamps: submission is sampled directly
before the authenticated frame write, and admission, first-token, and terminal
times are sampled immediately after the corresponding checked native events.
A separate public multi-step probe would have to leak a live client/owner
lifetime across caller-controlled awaits and would weaken cancellation and
cleanup ownership. The adapter therefore constructs a fixed one-request
LunaFlux collector internally and returns evidence only after deterministic
listener, service, worker, scheduler, and KV cleanup.
